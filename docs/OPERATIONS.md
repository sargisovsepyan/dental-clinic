# Operations and explicit provider smoke

All procedures below require an approved environment, restricted operator, injected credentials (never command-line URI/password), synthetic data and recorded safe pass/fail evidence. Phase 4A does NOT execute them against real services. Unit/CI/preview/health never send provider email, uploads or challenge requests.

## Health, process and observability

`GET /api/v1/health/live` (legacy `/health`) returns minimal200 `{success:true,status:"live"}` without dependency probes. `GET /api/v1/health/ready` returns200/503 with only ready/not_ready and uses cached single-flight Mongo ping + Redis ping, bounded by HEALTH_CHECK_TIMEOUT_MS. It does not probe SMTP/Cloudinary/Turnstile/monitoring or expose credentials/topology. HTTPS is still enforced: configure probes through the trusted HTTPS edge or the restricted proxy forwarding chain, not spoofed headers from arbitrary clients. Readiness has a per-process abuse limit60/min; size/frequency probes accordingly. Drain sets readinessfalse and rejects new application work; traffic removal BEFORE SIGTERM is the operator's first step.

API and worker shutdown deadlines include in-flight work AND DB/Redis/report cleanup. Worker abort stops the next claim batch, including after its asynchronous sweep; current delivery can settle boundedly. A killed worker leaves durable leases that expire and are reclaimed. Keep platform kill grace above GRACEFUL_SHUTDOWN_TIMEOUT_MS. Restart/supervise fatal nonzero exits, but investigate config/prerequisite failures rather than infinite restart loops. Next `start` uses its framework SIGTERM/SIGINT behavior; platform drain/kill deadline is mandatory, never use development server in production.

Structured backend logs contain timestamp, level, fixed event, processRole, safe route template (or `/unmatched`), method/status/duration, generated request ID, and sanitized error category. URI credentials, bearer/JWT/cookies/password/token/email/phone/patient fields are redacted; production internal Error messages/stacks are not emitted. Arbitrary URL segments/query/body/header content is not logged. Edge/web hosting access logs MUST independently omit query strings, auth/cookie/body, and raw resource IDs; disable verbose Next/Redis/provider debug logging. Restrict log access and approve retention. Business audit projections remain separate and immutable; their sensitive metadata sanitization is unchanged. The existing HTTPS monitoring adapter sends minimal generic context, no patient data; provision endpoint/alerts/privacy agreement later, no vendor added.

Alert on readiness5xx, DB/Redis outages, repeated restart/startup failure, notification oldest-due age, claimed/sent/retry/failure counts, expired leases, terminal failures, cleanup debt, backup/job failures and dependency alerts. No patient body/address or credential is an alert label. Global Redis namespace is `dental-clinic:rate-limit:<limiter>:<HMAC/IP-key>`; use a dedicated logical DB or service for each environment. Required ACL includes PING, SCRIPT LOAD, EVALSHA and limiter key commands (GET/SET/INCR/PTTL/DECR/DEL); verify provider scripting support, not just successful PING. Offline or stalled limits fail closed, never substitute in-process memory. A lost Redis cache can reset abuse windows; choose availability/persistence accordingly, but Redis is NOT booking lock authority.

## Read-only checks versus apply

Configuration-only permits reserved syntactic endpoints for provider-free CI; full preflight and production process startup reject them before any connection. Actual release endpoint/key ownership remains an operator check. Library DEBUG/NODE_DEBUG/inspector output is rejected in backend production configuration. The normal isolated smoke API uses explicitly disposable test mode and never bypasses these production guards for a release.

From backend: `npm run production:preflight -- --config-only` validates production schema/mode/runtime with NO network contact. Exit1 is a release blocker; output never prints secret values, URIs or stacks. `npm run production:preflight` additionally connects MongoDB/Redis, checks selected database identity, transactional topology, complete critical catalog/ledger and business/outbox invariants. It is read-only and has a90s wall-clock deadline. Run its full business scan during the runbook's stopped-write window; an active legitimate notification lease is a blocker to that drained preflight, not an ordinary runtime health failure. Integration presence is NOT provider delivery certification. No SMTP/Cloudinary/challenge/monitoring calls are made by either preflight mode. Startup uses only the lighter prerequisites, so healthy concurrent workers do not block API restart.

`npm run migrate` defaults dry-run; apply is explicit and requires evidence/drained writers. `npm run production:indexes` is explicit non-dropping APPLY with duplicate pre-scan; ordinary preflight/startup never calls it. Never use syncIndexes, delete conflicts or erase ledger leases. `npm run reconcile:appointment-quota` defaults dry-run; inspect before --apply. `npm run reconcile:media -- --limit=50` DOES delete eligible unreferenced provider assets and updates cleanup jobs; scheduler must use approved credentials/maintenance acknowledgement, safe timeout and durable-lock-aware supervision. Alert on terminal failed cleanup rather than ignoring it.

## Provider smoke procedures (later, explicit)

1. **MongoDB / Redis (non-destructive connectivity):** inject reviewed production configuration, run config-only and full drained preflight, record only booleans/counts and exit status. MongoDB target must be the approved database with transaction-capable topology and exact indexes. PING alone is insufficient; through the gateway use one harmless public API GET to exercise lazy Redis script loading/limit increment and inspect generated request ID/status; never publish URI/user/password. Timebox to90s preflight and10s request; failures block traffic. Rate-limit cache increments are expected, not business mutations.
2. **SMTP (one deliberate synthetic email):** choose a clinic-approved operator-owned recipient, never a patient. In a restricted operator Node session load the default `createSmtpAdapter` export (`src/mail/smtp.adapter.js`), then explicitly call `send` once with fixed synthetic subject/body and unique non-sensitive Message-ID, OR use an equivalent operator SMTP test client with mandatory verified TLS/timeouts. Use injected validated SMTP settings, never print transport configuration/provider response. Apply a hard60s operator process deadline in addition to configured DNS/connect/greeting/socket bounds. Record only accepted/rejected and independently verify mailbox arrival/sender/SPF/DKIM/DMARC; delete synthetic mailbox content. An approved synthetic booking then verifies separate-worker outbox delivery; clean up via normal cancellation/retention, not arbitrary DB edits. Staff credential delivery is separate SMTP, not appointment outbox.
3. **Cloudinary (mutating disposable asset):** restricted operator session uses existing SDK/adapter with injected credentials and a locally generated tiny non-person image. Unique synthetic public ID under an approved `deployment-smoke/` namespace; type=image, overwrite=false, no patient content. Bound upload/resource/destroy operations to10s each (SDK timeout plus hard operator process deadline60s). Verify authoritative `resource(publicId)` public ID, image type, format/size and allowlisted secure URL; then in a finally block destroy exactly that ID and confirm resource-not-found. Capture only success/failure and a safe opaque evidence ID, never signed URL/key/secret/provider body. Failure to delete creates explicit operator cleanup debt and blocks media certification; do not delete by a prefix or affect real assets. Test normal governed UI WebP normalization/replacement and two-image pair rollback separately with synthetic clinic-approved fixtures after provisioning. Never create fake consent to make a real patient image publishable. Existing magic-byte, WebP, public-ID, CAS/reference, rollback, pair, withdrawal/purge controls remain mandatory.
4. **Turnstile (manual domain/browser):** provision public/secret key pair with the exact approved public hostname(s), no wildcard/unrelated hosts, and restrict dashboard access. Rebuild frontend with actual PUBLIC key; backend keeps SECRET private. On the real HTTPS public site solve the widget, submit ONE approved synthetic booking, verify server-side Siteverify success. Invalid/expired/reused token must fail400, provider unavailability503; retry uses established booking idempotency/challenge rules. Block the provider in browser/network to verify visible failure and no silent bypass. No CLI token shortcut, fake hostname evidence or fake consent. Clean the synthetic appointment through normal cancellation, not direct lock deletion.

Readiness/config validation does not verify mail reputation, delivery, Cloudinary deletion, challenge hostname ownership, monitoring/backup activation or TLS gateway configuration. These are explicit protected deployment gates.

## Safe local production-build smoke

From frontend, build with public-only reserved same-origin fixtures (`NEXT_PUBLIC_SITE_URL=https://clinic.example.test`, `NEXT_PUBLIC_API_URL=https://clinic.example.test/api/v1`, challenge=turnstile, public key=public-config-only-key, telemetry disabled), then run `node test/production/run-production-smoke.mjs`. Install both lockfiles first; Playwright Chromium and existing mongodb-memory-server binary must be available. A missing binary may use the test package's normal disposable binary download/cache, not a service database.

This starts the REAL compiled Next `start`, a REAL API in explicitly isolated test mode, disposable Mongo replica set, and synthetic fixture identities. The test-only preload/browser boundary routes only the fixed reserved origin to loopback and blocks external fetches. It verifies SSR/API connectivity, production headers, secure Strict HttpOnly path-scoped refresh login/rotation/logout, admin, public booking, health and owned shutdown/port release. It retains `.next` as the normal production BUILD artifact, creates no preview/E2E dist cache and never imports fixtures into application code. On Windows IPC invokes the actual API SIGTERM handler (Windows child.kill cannot deliver POSIX signals); web termination is owned/bounded. This is NOT real backend production-provider mode, real TLS/DNS gateway certification, real Turnstile or provider smoke. Real-mode config/prerequisite/failure gates have separate provider-free regressions. The existing broad E2E uses Next dev and is reported separately, never as production verification.
